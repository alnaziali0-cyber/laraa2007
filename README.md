# نواة | لوحة استضافة مشاريع Python

لوحة عربية RTL لإدارة الملفات ومشاريع Python. مبنية على **FastAPI + SQLite + واجهة HTML/CSS/JavaScript**. بيانات الحسابات والملفات محفوظة في مجلد خاص خارج المجلد العام `static/`.

## ما يعمل فعليًا

- إنشاء الحسابات وتسجيل الدخول والخروج، جلسات بملفات تعريف ارتباط HttpOnly، كلمات مرور مجزأة بـ PBKDF2، صلاحيات مدير للحساب الأول، وفصل الوصول إلى مساحة كل مستخدم.
- لوحة إحصائيات فعلية للمشاريع والمساحة والملفات وحدود الخدمة المتاحة. لا تعرض CPU/RAM تخمينية.
- رفع متعدد مع تقدم XHR حقيقي؛ الحد الافتراضي 25 MiB لكل ملف. قائمة ملفات، إنشاء المجلدات، إعادة تسمية/نسخ/نقل/حذف/تنزيل، معاينة وتحرير النصوص، وفك/إنشاء ZIP مع فحوص المسارات والعدد والحجم وحصة التخزين.
- مشاريع، تحديد ملف التشغيل، تشغيل/إيقاف/إعادة تشغيل، وحالة/PID/سجلات Docker عند توفر مشغّل الحاويات.
- لوحة مدير للمستخدمين وسجل العمليات والموارد التي يمكن للنظام قياسها.

## حدود مهمة قبل الاستخدام

- بيئة التطوير الحالية **لا يتوفر فيها Docker**. اختبرت سلوك منع التشغيل عند غياب Docker، ولم تُشغّل أكواد مستخدم أو حاويات فعلية هنا. تشغيل التطبيقات الطويلة يتطلب خادم Linux مخصصًا مع Docker daemon وإتاحة Docker CLI/socket. مشاركة المقبس مخاطرة عالية؛ الأفضل فصل خدمة المشغّل بصلاحيات محدودة ومضيف مخصص.
- تشغيل الحاوية المحدد يفرض: `--network none`، مستخدم غير root، filesystem قراءة فقط، قدرات مسقطة، و256 MiB RAM و0.5 CPU و128 PID. الحاوية تأخذ ملفات المشروع قراءة فقط. لذلك لا تستطيع البرامج حفظ ملفات أو سجلات داخل المشروع أثناء التشغيل.
- تثبيت `requirements.txt` **غير منفذ**؛ الحاوية الحالية Python 3.12 نظيفة، ولا تدّعي تثبيت اعتماديات المشروع. يلزم تطوير مسار build معزول للاعتماديات قبل تشغيل مشاريع تحتاج حزمًا خارجية.
- stdin غير منفذ. التحديث التلقائي للسجلات يتم بالاستطلاع كل 5 ثوان. عرض السجلات حدّه 200 سطر/200KB.
- الثيم الفاتح/الداكن متاح؛ الواجهة الإنجليزية وتخصيص الألوان يدويًا غير منفذين بعد. إصدار Python الوحيد المعلن هو 3.12، وفق الصورة المحددة.
- حدود المستخدم (5 مشاريع/512 MiB) إعدادات خادم وليست لوحة تعديل حصص تفاعلية لكل حساب. التسجيل المفتوح يمنح أول حساب صفة المدير؛ أغلق التسجيل أو أضف دعوات قبل النشر العام.
- غير جاهز لاستضافة عامة إنتاجية دون CSRF token، rate limiting، مراقبة متعددة الطبقات، سياسة retention/backup، تنقيح أسرار السجلات، ومراجعة أمنية مستقلة.
- Static hosting وحدها مثل Cloudflare Pages لا تشغّل عمليات Python دائمة. رابط معاينة التطوير مؤقت ولا يمثل استضافة بوتات 24/7.

## متطلبات وتشغيل محلي

Python 3.12+. Docker مطلوب لتشغيل أكواد المستخدم بأمان.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app:app --host 0.0.0.0 --port 8000
```

افتح `http://localhost:8000`. يجب أن تتكون كلمة المرور من 10 أحرف على الأقل.

## متغيرات البيئة

| المتغير | القيمة الافتراضية | الاستخدام |
|---|---:|---|
| `HOSTPANEL_DATA_DIR` | `./private-data` | قاعدة البيانات وملفات المستخدمين الخاصة خارج `static/` |
| `MAX_FILE_BYTES` | `26214400` | أقصى حجم للملف |
| `USER_QUOTA_BYTES` | `536870912` | حصة التخزين لكل حساب |
| `MAX_PROJECTS` | `5` | أقصى مشاريع الحساب |
| `RUNNER_IMAGE` | `python:3.12-slim` | صورة الحاوية المثبتة |
| `COOKIE_SECURE` | `0` | اضبط `1` خلف HTTPS |

## النشر على خادم

1. ابنِ صورة `Dockerfile` وانشرها على مضيف يدعم خدمة طويلة التشغيل.
2. اربط حجمًا دائمًا إلى `/var/lib/nawahost`، واحفظ بيانات SQLite والملفات خارج الويب العام.
3. يحتاج المشغّل Docker CLI وDocker daemon. مثال التشغيل التقليدي أدناه يربط Docker socket؛ لا تستخدم هذا الإعداد دون عزل مضيف/خدمة مناسبين، لأن السيطرة على المقبس تعادل عمليًا صلاحيات واسعة على المضيف.
4. ضع reverse proxy مع HTTPS وحدود أحجام/معدلات، واضبط `COOKIE_SECURE=1`. فعّل نسخًا احتياطية وإغلاق التسجيل العام.

```bash
docker build -t nawahost .
docker run -d --name nawahost-panel -p 8000:8000 \
  -v nawahost-data:/var/lib/nawahost \
  -v /var/run/docker.sock:/var/run/docker.sock nawahost
```

## الاختبارات

```bash

pytest -q
```

تغطي الاختبارات المصادقة والصلاحيات، الرفع والمعاينة والحفظ والتنزيل، فحص واستخراج ZIP ومنع Zip Slip، المسارات غير الآمنة، ملف تشغيل مفقود، وحالة Docker غير المتاح.
