# Sea Host — استضافة خاصة لمشاريع Python

لوحة عربية RTL لإدارة ملفات ومشاريع Python، مع دخول خاص بمالك واحد، ورمز تحقق بالبريد، وفصل API الويب عن عامل Docker داخلي محدود بواجهة أوامر مسموح بها. يتكون المشروع من FastAPI وSQLite وواجهة HTML/CSS/JavaScript وخدمات Compose.

## ما تنفذه النسخة

- **المطور المسموح:** البريد `aaaq70232@gmail.com` هو الافتراضي في الإعداد، ولا يوجد تسجيل عام. ينشأ الحساب محليًا بأداة تفاعلية؛ لا تمر كلمة المرور في command line أو Git. كلمات المرور Argon2id، مع ترقية تلقائية لصيغة PBKDF2 القديمة عند نجاح تسجيل مالك مطابق.
- **دخول بخطوتين:** كلمة مرور ثم OTP من ستة أرقام، صالح خمس دقائق، مخزن كـ HMAC، بحد أقصى خمسة تخمينات ويُبطل بعد الاستخدام. توجد حدود للمحاولات، وsession cookie من نوع HttpOnly، ورمز CSRF مستقل، وتكوين Secure/SameSite بحسب إعداد HTTPS.
- **البريد وCAPTCHA:** إرسال SMTP مع STARTTLS أو TLS ضمن أسرار الخادم؛ لا يُعلن نجاح الإرسال عند نقص الإعداد. CAPTCHA اختياري عبر Cloudflare Turnstile ويتحقق منه الخادم عند تشغيله.
- **اكتشاف نقطة التشغيل:** الإعداد الصريح المحفوظ يتقدم على الكشف. بعده `Procfile` ثم نقاط `project.scripts` في `pyproject.toml` ثم `Dockerfile`، ثم تحليل AST ساكن لـ Python. لا يشغّل الكشف كود المشروع؛ أسماء `main.py` و`bot.py` و`app.py` تلميحات فقط. تُعرض الخيارات المتعددة للمطور، وتُتطلب نقطة صريحة عند الغموض أو عدم وجود دليل كافٍ. يدعم فحص تعريفات ZIP دون تنفيذها.
- **الملفات وZIP:** رفع متعدد وتقدم حقيقي، مجلدات، إعادة تسمية/نسخ/نقل/حذف/تنزيل، معاينة/تحرير نصوص، إنشاء وفحص واستخراج ZIP مع منع Zip Slip وحدود الحجم/العدد وحصة المستخدم.
- **المشاريع:** إنشاء وتحديد نقطة التشغيل وكشفها وتثبيت `requirements.txt` أو `project.dependencies` من `pyproject.toml` عند جذر المشروع أو مجلد مصدره في Docker معزول، تشغيل/إيقاف/إعادة تشغيل، حالة وPID وسجلات وتنزيلها. تميّز اللوحة خروج العملية بخطأ عن الإيقاف، وتحفظ آخر 200KB قبل استبدال الحاوية؛ حالة التشغيل وقفل العمليات مستمران في SQLite ومحرك الحاويات.
- **لوحة واحدة:** نظرة عامة، مدير ملفات، المشاريع، سجلات مستقلة، موارد قابلة للقياس، وإعدادات خدمة غير سرية.

## العزل الفعلي وحدوده

- **بيئة هذه المهمة لا تحتوي Docker**؛ فشل `docker compose config` لأن الأمر التنفيذي `docker` غير موجود. لذلك لم تُنشأ أو تُشغّل حاويات فعلية هنا، ولم يُختبر بناء Docker أو تثبيت حزم مستخدم داخلها. API يعيد حالة عدم الإتاحة بدل الادعاء بالتشغيل.
- على خادم مدعوم، كل مشروع يأخذ حاوية بمستخدم `10001:10001`، شبكة `none`، filesystem للبرنامج read-only، قدرات مسقطة، `no-new-privileges`, `256 MiB` RAM، `0.5 CPU`، `128 PIDs`، و`/tmp` مؤقتًا بحد `32 MiB`. السجل `json-file` محدود إلى `10 MiB × 3` ملفات. يوجد حد CPU-time تراكمي قدره 24 ساعة للعملية، وهو **ليس** مؤقتًا زمنيًا للحائط؛ الخدمة طويلة العمر قد تبقى أطول إذا ظلت خاملة.
- لا تركّب لوحة الويب Docker socket. المقبس يركّب فقط في خدمة `runner` المنفصلة على شبكة Compose داخلية، ولا تنشر منفذها للعامة؛ يتحقق العامل من سر داخلي ويقبل مجموعة ضيقة من أوامر Docker وأسماء الحاويات والمسارات. هذا يقلل سطح التعرض لكنه لا يلغي حقيقة أن خدمة runner التي تتصل بمقبس Docker تمثل امتيازًا عاليًا على المضيف؛ استخدم مضيفًا مخصصًا وجدارًا ناريًا وتحديثات أمنية.
- حاويات المشاريع لا تتصل بالإنترنت أو الشبكات الداخلية افتراضيًا (`--network none`). هذا يمنع أيضًا اتصال البوتات بخدمات خارجية. تثبيت الحزم معطل شبكيًا افتراضيًا؛ لتفعيله أنشئ شبكة Docker اسمها `seahost-build-egress` بسياسة جدار ناري تمنع النطاقات الخاصة وخدمات الإدارة وتسمح فقط بمرايا الحزم العامة، ثم اضبط `RUNNER_BUILD_NETWORK=seahost-build-egress`. **لا توصل شبكة bridge العامة مباشرة.**
- الرفع والتحرير وفك ZIP والنسخ تحترم حصة `USER_QUOTA_BYTES`. قياس هذه الحصة لا يعادل project quota من نظام الملفات، ولا يفرض Docker افتراضيًا حدًا على حجم طبقة الصورة أو على البيانات المؤقتة داخل عمليات البناء. فعّل حصة تخزين فعلية على مستوى Linux/نظام الملفات، وراقب مساحة Docker، قبل استخدام حسابات حقيقية.
- CPU/RAM لا يعرضهما النظام كقياس تخميني؛ لوحة الموارد تسأل Docker عن إحصاءات الحاويات عند توفره. سجلات Docker محدودة بالتدوير أعلاه؛ تحفظ اللقطة الأخيرة عند توقف الحاوية أو استبدالها بحد 200KB. عامل داخلي يفحص دوريًا (كل ساعة) ويحذف الحاويات المتوقفة ولقطاتها بعد `LOG_RETENTION_DAYS` (7 أيام افتراضيًا)، وتزال اللقطات القديمة أيضًا عند قراءتها أو بدء التطبيق.
- لا تتلقى حاويات المشاريع أسرار SMTP أو مفتاح الجلسة أو سر runner. إعدادات الخادم لا تكشف قيم الأسرار. استضافة عامة ما تزال تتطلب مراجعة أمنية واختبار Docker فعليًا، TLS/Reverse proxy مع حد معدلات، نسخًا احتياطية لخارجية SQLite/البيانات، وحصص filesystem موثوقة.

## التثبيت على خادم Linux

لخطوات Ubuntu 24.04 المفصلة على جهازك الدائم، بما فيها DNS وHTTPS وSMTP وDocker، راجع [دليل النشر الذاتي بالعربية](DEPLOY_HOME_AR.md).

المتطلبات: Docker Engine + Compose plugin، خادم Linux مخصص، مساحة بيانات host ثابتة، اسم نطاق وHTTPS أمام اللوحة. Compose يربط Docker socket **بخدمة runner فقط**؛ لا تستخدمه على جهاز مشترك متعدد المستأجرين دون عزل مضيف مناسب.

```bash
gh repo clone alnaziali0-cyber/laraa2007
cd laraa2007
cp .env.example .env
# أنشئ سرين مستقلين ثم استبدل القيم الوهمية داخل .env:
openssl rand -hex 32  # RUNNER_TOKEN
openssl rand -hex 32  # APP_SECRET_KEY
sudo install -d -o 10001 -g 10001 -m 0750 /srv/seahost-data
# عدل /srv/seahost-data، البريد وإعدادات SMTP في .env، واحفظه بصلاحية خاصة:
chmod 600 .env
```

استخدم في Gmail **App Password** خاصًا بالبريد، وليس كلمة مرور حساب Google. ضع القيمة في `SMTP_PASSWORD` على الخادم فقط؛ لا ترسلها في المحادثة ولا تضفها إلى Git. يجب تفعيل 2-Step Verification لحساب Google لإنشاء App Password. ضبط البريد غير ممكن من هذه البيئة لأن سر SMTP لم يُقدّم ولم يُحفظ فيها.

```bash
docker compose build
docker compose run --rm --no-deps panel python create_owner.py
docker compose up -d
```

تأكد أن `HOSTPANEL_DATA_DIR` في `.env` مسار مطلق على المضيف، وأنه نفس المصدر الذي يراه Docker daemon. يرتبط المنفذ 8000 بـ `127.0.0.1` افتراضيًا؛ ضع Reverse Proxy بـ HTTPS على المضيف أمامه واضبط `COOKIE_SECURE=1` قبل فتح الخدمة على الإنترنت. إذا استخدمت Reverse Proxy داخل حاوية، عدّل ربط المنفذ لتصل إليه مع إبقاء لوحة Sea Host محمية بـ HTTPS. لا تنشر `runner:8091`.

### شبكة تثبيت الحزم الاختيارية

إذا أردت تثبيت الحزم من PyPI، جهّز شبكة منفصلة باسم `seahost-build-egress` **على المضيف**، وطبّق قواعد firewall على المضيف تمنع عناوين RFC1918/loopback/link-local/metadata ومنافذ الإدارة، وتسمح فقط بخروج HTTPS إلى مزود/مرآة الحزم المطلوبة. بعد اختبار هذه السياسة، اضبط `RUNNER_BUILD_NETWORK` في `.env`. الوضع الافتراضي `none` أكثر أمانًا لكنه لا يستطيع تنزيل الحزم.

### تشغيل التطوير المحلي (دون حاويات مشاريع)

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# محليًا: اضبط مسار بيانات قابلًا للكتابة وSecure cookie=0 في .env
# جهز سر APP_SECRET_KEY وSMTP قبل استخدام المصادقة الثنائية
HOSTPANEL_DATA_DIR="$PWD/private-data" python create_owner.py
HOSTPANEL_DATA_DIR="$PWD/private-data" uvicorn app:app --host 127.0.0.1 --port 8000
```

أنشئ الحساب الأول محليًا عبر `python create_owner.py`. تهيئة الحساب وحدها لا تكفي للدخول؛ OTP يتطلب SMTP يعملًا، وCOOKIE_SECURE يجب أن يبقى 0 محليًا دون HTTPS.

## متغيرات أساسية

| المتغير | الغرض |
|---|---|
| `OWNER_EMAIL` | البريد الوحيد المسموح؛ الافتراضي `aaaq70232@gmail.com` |
| `APP_SECRET_KEY` | سر عشوائي خاص لتوقيع/تجزئة OTP؛ 32 بايت على الأقل |
| `SMTP_HOST/PORT/USERNAME/PASSWORD/FROM` | إعداد SMTP؛ كلمة مرور التطبيق تبقى في `.env` الخاص |
| `COOKIE_SECURE` | `1` في HTTPS الإنتاج، و`0` للتطوير المحلي عبر HTTP |
| `RUNNER_API_URL`, `RUNNER_TOKEN` | عنوان وسر اتصال لوحة الويب بالعامل الداخلي |
| `HOSTPANEL_DATA_DIR` | مسار البيانات الدائم المطلق على المضيف |
| `RUNNER_BUILD_NETWORK` | `none` افتراضيًا؛ لا تستخدم إلا الشبكة المقيدة المذكورة أعلاه |
| `MAX_FILE_BYTES`, `USER_QUOTA_BYTES` | حد الملف وحصة ملفات المستخدم |
| `MAX_PROJECTS`, `MAX_RUNNING_PROJECTS` | حد المشاريع والتشغيل المتزامن |
| `LOG_RETENTION_DAYS` | صلاحية لقطات السجلات المحفوظة (1–365 يومًا، الافتراضي 7) |

كل الأسرار في `.env`، وهو مستثنى من Git وDocker build context. لا تضع مفاتيح أو كلمات مرور في ملفات JavaScript/HTML أو ملفات المستودع.

## الاختبارات المتاحة

```bash
pip install -r requirements.txt
pip install pytest httpx
python -m py_compile app.py create_owner.py runner_worker.py tests/*.py
node --check static/app.js
pytest -q
```

اختبارات API تستخدم محرك Docker وهميًا لاختبار شكل الأوامر وقيودها؛ لا تُعد اختبارًا بديلًا عن Docker daemon. الاختبارات الحالية تغطي OTP وحد محاولاته وArgon2 وحظر التسجيل والبريد غير المصرح وCSRF ومعدل المحاولات وانتهاء الرمز، رفع/تحرير/تنزيل الملفات وZIP Slip والحصص، كشف نقطة التشغيل، فشل التشغيل دون Docker، كشف انهيار المشروع والاحتفاظ بسجلاته، منع البدء المتزامن، وتوليد أوامر التثبيت والتشغيل والإيقاف بحدود العزل.
